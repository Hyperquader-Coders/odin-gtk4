# Patched bindings

The bindings are generated by [runic](https://github.com/Samudevv/runic) from the C headers.
Regenerating overwrites hand fixes, so each is also pinned by a typed variable in the
package's `patched.odin`: a regeneration that drops a patch fails to compile there instead
of misbehaving at run time.

To regenerate, run `make generate`, re-apply every row below, and build the package.

## Generation rules

`scripts/postprocess.sh gtk4` applies these to `gtk4/gtk4.odin`. They are odin-gtk's rules,
trimmed to what runic 0.8 produces from the staged headers.

| rule | reason |
|---|---|
| `^glib.char` and `[^]glib.char` become `cstring` | `gchar *` is a typedef'd char pointer, which runic leaves as a pointer to `char` |
| `cairo.t` becomes `cairo.context_t` | odin-cairo's name for the context |
| `TYPE_*`, `*_ERROR`, `ACCESSIBLE_LIST` and other constants of the form `` `(gtk_foo_get_type ())` `` become `gtk_foo_get_type`-style names without backticks, parentheses or the `gtk_` prefix | macro text runic quotes as a string; `TYPE_FOO` then names `foo_get_type` |
| `MAJOR_VERSION`, `MINOR_VERSION`, `MICRO_VERSION` and `VERSION_*` lose their backticks | the version test reads them as numbers |
| `PRIORITY_*`, `BUTTON_*`, `TREE_SORTABLE_*`, `ACCESSIBLE_VALUE_UNDEFINED`, `CURRENT_TIME`, `EVENT_STOP`, `EVENT_PROPAGATE`, `INVALID_LIST_POSITION`, `ENTRY_BUFFER_MAX_SIZE`, `MEMORY_DEFAULT`, `UNIT_PIXEL` become Odin expressions | C literals and aliases runic quotes |
| the GFlags enums listed in `postprocess.sh` (`gtk4_flags`) become `FooBit :: enum u32` of bit indices plus `Foo :: bit_set[FooBit; u32]`; zero members and composite masks become constants of `Foo`; `MODIFIER_MASK` and `ACTION_ALL` become `ModifierType{...}` and `DragAction{...}` | `{.SHIFT_MASK, .CONTROL_MASK}` instead of u32 ORs; the size and bits are those of C; see DECISIONS §5 |
| `Foo :: _GtkFoo` is deleted and `_GtkFoo` becomes `Foo` (likewise `_Gdk`, `_Gsk`) | one name per struct |
| an identical one-line declaration seen twice keeps the first | `GtkSnapshot` is `GdkSnapshot`; `Snapshot`, `SnapshotClass` and `TYPE_SNAPSHOT` come out twice |
| `parameters: declared` in `gtk4/rune.yml` makes every procedure parameter `^T` (`T **` is `^^T`); only the 63 parameters of the procedures listed under `to.detect.arrays` are `[^]`; the parameters in `scripts/single-object-params.*.txt` are pinned once per type in `patched.odin` | runic writes `[^]T` for any pointer parameter whose name ends in `s` (`settings`, `bounds`, `focus`, `n_types`...), and `[^]^T` for `T **`; a `[^]` on one object lets a caller index past it. The arrays were chosen against the C headers and the gtk-doc `(array)` annotations; `scripts/check-generated.sh` fails if a `[^]` parameter is not in `arrays:` or a listed single object is `[^]` again. Function-pointer types are always `^T` in this mode, so `param_rules` in `postprocess.sh` gives their parameters the types runic's name guess wrote before (`[^]T`, which includes the real arrays: `colors`, `uris`, `pts`, `attribute_names`); a row that matches nothing fails generation |
| a procedure whose last C parameter is a `va_list` is not generated; the foreign block carries a `// name skipped` comment | runic drops a trailing `va_list` and marks the procedure `#c_vararg ..any`, which is a wrong call; the fork skips it, and `check-generated.sh` holds the list of skipped names. Real `...` procedures (`list_store_insert_with_values`) are bound |

`scripts/type-casts.sh` writes `gtk4/type_casts.odin`: `FOO` and `IS_FOO` for every
`TYPE_FOO :: foo_get_type` in `gtk4.odin` that is a class, interface or instantiatable
fundamental type; error domains, enums, flags and boxed types are skipped (DECISIONS §6).

## `gtk4`

`rune.yml` overwrites `GtkSnapshot`, `GtkSnapshotClass` and `GTK_TYPE_SNAPSHOT` with their GDK
originals, and ignores the `_*`, `*DEPRECATED*` and `*AVAILABLE*` macros, `GTK_BINARY_AGE`,
`GTK_INTERFACE_AGE`, `GDK_CAIRO_ERROR` and `GTK_TYPE_TREE_ROW_DATA`.

| symbol | patch | reason |
|---|---|---|
| `snapshot_append_border`, `gsk_border_node_new` | `border_width` and `border_color` are `^[4]f32` and `^[4]RGBA` | a C array parameter decays to a pointer; by value it is passed wrongly |

The fork also patched `gdk_texture_downloader_download_bytes_with_planes`. GTK 4.16 does not
have it, so there is nothing to patch.

Pins, in `gtk4/patched.odin`: `patched_snapshot_append_border`, `patched_border_node_new`,
`patched_cairo_set_source_rgba` (the cairo type rule) and `patched_check_version` (the
`cstring` rule).

Graphene, cairo, pango and gdk-pixbuf types come from their packages, not from this one.
